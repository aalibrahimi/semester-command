Read `SPEC.md` §2.0 and §3 first. This file is the implementation order plus reference skeletons for the parts most likely to be gotten wrong. Everything here is Rust unless noted.

**Deliverable:** a debug route that dumps every synced entity, working under both auth modes. No production UI in this milestone.

## 1. AuthMode

Both auth paths must sit behind one interface so a token can replace cookies with a one-line change if SJSU's admins issue one.

```rust
/// How we prove identity to Canvas.
///
/// SJSU disables student-generated access tokens, so `Session` is the live path.
/// `Token` exists because an admin-issued token would make everything simpler,
/// and swapping should not require touching call sites.
#[derive(Clone, Debug)]
pub enum AuthMode {
    Token(String),
    Session { cookie_header: String },
    /// No credentials — ICS feed + manual entry only.
    None,
}

impl AuthMode {
    /// Applies credentials to an outgoing request.
    pub fn apply(&self, req: reqwest::RequestBuilder) -> reqwest::RequestBuilder {
        match self {
            AuthMode::Token(t) => req.bearer_auth(t),
            AuthMode::Session { cookie_header } => req.header(reqwest::header::COOKIE, cookie_header),
            AuthMode::None => req,
        }
    }
}
```

Always send `Accept: application/json+canvas-string-ids`. Canvas IDs exceed JS safe-integer range; string IDs avoid silent precision loss.

## 2. Login webview and cookie harvest

**The single most important constraint in this milestone:** cookie reads must run in an `async` command, off the main thread. Reading cookies from a sync command or an event handler deadlocks WebView2. It manifests as the entire app freezing with no error and no panic.

```rust
/// Opens the SJSU Canvas login window. The user authenticates through SSO
/// themselves — we never see or store the password.
#[tauri::command]
async fn open_canvas_login(app: tauri::AppHandle) -> Result<(), String> {
    tauri::WebviewWindowBuilder::new(
        &app,
        "canvas-login",
        tauri::WebviewUrl::External("https://sjsu.instructure.com/login".parse().unwrap()),
    )
    .title("Sign in to Canvas")
    .inner_size(900.0, 750.0)
    .build()
    .map_err(|e| e.to_string())?;
    Ok(())
}

/// Harvests session cookies after login.
///
/// MUST be async. See the WebView2 deadlock note above — this is not optional
/// on Windows, it is the expected failure.
#[tauri::command]
async fn harvest_session(app: tauri::AppHandle) -> Result<bool, String> {
    let win = app.get_webview_window("canvas-login").ok_or("login window not open")?;
    let cookies = win
        .cookies_for_url("https://sjsu.instructure.com".parse().unwrap())
        .map_err(|e| e.to_string())?;

    // Canvas's session cookie. Name has changed across Canvas versions —
    // log every cookie name the first time and confirm against reality
    // rather than trusting this constant.
    let has_session = cookies.iter().any(|c| c.name() == "canvas_session");
    if !has_session {
        return Ok(false);
    }

    let header = cookies
        .iter()
        .map(|c| format!("{}={}", c.name(), c.value()))
        .collect::<Vec<_>>()
        .join("; ");

    store_in_keyring(&header)?;
    win.close().map_err(|e| e.to_string())?;
    Ok(true)
}
```

Notes:
- **Verify `cookies_for_url`'s exact signature against the Tauri version in `Cargo.toml`.** This API is recent and the shape may differ. Do not guess — check the docs, and if it isn't available, upgrade Tauri rather than working around it.
- Cookies only come back for `http`/`https` URLs, never `tauri://`.
- Poll for the session cookie every 2s while the login window is open, up to 5 minutes, then give up with a clear message. SSO plus MFA is slow; don't time out at 30 seconds.
- Storage: `keyring` crate → Windows Credential Manager. Service name `semester-command`, username `canvas-session`.

## 3. Session-dead detection

Treat all three of these as "session expired", not as errors to retry:
- HTTP `401`
- A `3xx` redirect to any host that isn't `sjsu.instructure.com` (SSO bounce)
- A `200` whose `Content-Type` is `text/html` where JSON was expected (Canvas serves the login page)

On any of them: mark the session dead in app state, emit an event the frontend listens for, show "Reconnect to Canvas" in the sidebar footer. Never retry automatically, never clear the local DB, never present stale grades without marking them stale.

## 4. Paginating, rate-limited GET

Every Canvas call goes through this. No exceptions.

```rust
/// Fetches all pages of a Canvas collection endpoint.
///
/// Pagination is driven by the `Link` header's rel="next", NOT by a page count —
/// Canvas does not return a total. Rate limiting is a leaky bucket exposed via
/// `X-Rate-Limit-Remaining`; below ~100 we back off rather than risk a 403.
pub async fn get_all<T: serde::de::DeserializeOwned>(
    &self,
    path: &str,
) -> Result<Vec<T>, CanvasError> {
    let mut url = format!("{}/api/v1{}?per_page=100", self.base, path);
    let mut out = Vec::new();

    loop {
        let resp = self.send(&url).await?;
        self.check_session_alive(&resp)?;

        if let Some(rem) = resp.headers().get("x-rate-limit-remaining")
            .and_then(|v| v.to_str().ok())
            .and_then(|v| v.parse::<f64>().ok())
        {
            if rem < 100.0 {
                tokio::time::sleep(std::time::Duration::from_secs(5)).await;
            }
        }

        let next = parse_link_header(resp.headers().get("link"));
        let body = resp.text().await?;
        // Persist raw JSON before parsing — if deserialization fails we still
        // have the response on disk to inspect.
        self.log_raw(path, &body);
        out.extend(serde_json::from_str::<Vec<T>>(&body)?);

        match next { Some(u) => url = u, None => break }
    }
    Ok(out)
}
```

Cap course-level concurrency at 4. Never `join_all` an unbounded set of course requests.

## 5. Models

Every field is `Option<T>`. Canvas omits keys constantly depending on course settings and permissions.

Do **not** use `unwrap_or_default()` on score fields — that silently turns a missing grade into a zero, which is the exact bug class this app exists to avoid. Missing must stay missing all the way into the grade engine.

## 6. Sync

Order matters — later entities reference earlier ones:

`courses` → `assignment_groups` → `assignments` → `submissions` → `instructors`

- Upsert by Canvas ID. Never wipe and rebuild.
- Set `source = 'api'` on everything written here.
- A failed course logs to `sync_log` and the run continues. One broken course must not abort the sync.
- Record `synced_at` per row.

## 7. Tier 2 — ICS + manual

Not a stub. Settings field for the calendar feed URL, an ICS parser (`icalendar` crate), assignments written with `source = 'ics'`. Plus manual create/edit of courses, groups with weights, assignments, and scores, written with `source = 'manual'`.

Test this path by disconnecting auth entirely. If the app is unusable without cookies, this step isn't done.

## 8. Debug route

`/debug`, dev-only (`import.meta.env.DEV`). Per entity: row count, last sync time, a raw JSON viewer, and the `sync_log` table. Buttons to trigger a sync, drop the session, and force the reconnect state.
